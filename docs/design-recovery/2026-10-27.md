## Repository-specific records

### D30 — Project Card Manager: a tactile atlas with a dependable data contract

**Use when:** When recovering Project Card Manager, portfolio canvases, card physics, pointer/worker protocols, or project-management integration.

[Recovered intent] The README describes a portfolio/project system with an interactive physics canvas, multipointer input, worker/WASM simulation, an API spec, code generation, database, and shared UI. Its ambition is organizing work through a physically engaging interface.

[Observed boundary] React 19/Vite, Express, Drizzle, OpenAPI/Orval, Rapier, and a binary pointer protocol are documented claims here; this pass did not inspect each implementation or execute codegen/worker tests. A sophisticated README should not automatically become an accepted runtime contract.

[Repair resolution — proposed] Give project identity, status, dependency, and evidence ordinary inspectable records. Treat canvas position, momentum, and arrangement as local view state unless a user explicitly saves an arrangement. Provide list/search/keyboard access with equivalent information. Validate pointer encoding/decoding and cancellation under the same versioned contract.

[Reimagined horizon] A project atlas that can be spatial, tactile, chronological, or tabular while preserving canonical records. It can feed Melodyfire/Constellation as a consumer rather than silently becoming another registry authority.

[Carry-forward test] One project is findable and editable from both canvas and list; dragging/quality changes cannot mutate status or provenance; pointer capture/release and worker disposal behave correctly.
